# Contributing

The project uses small, reviewable pull requests.

Each pull request should:

1. state one mathematical or infrastructure goal;
2. keep the library compiling;
3. avoid `sorry`;
4. add documentation for new public declarations;
5. update `BLUEPRINT.md` when a milestone changes status.

Experimental work belongs on a feature branch. Code intended for Mathlib should
be kept sufficiently general and documented to support later upstreaming.
